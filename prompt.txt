## 1. Product vision

The website must feel like a designed digital experience rather than a conventional developer template. It should have the visual quality of a premium Wix Studio or Awwwards-inspired website, with original layouts, thoughtful interactions, and a recognizable visual identity.

The visitor should understand three things within the first few seconds:

- Who Abdullah is and what he builds.
- Which technologies he works with.
- Where to explore his projects or contact him.

The uploaded 3D character will be the visual centerpiece of the hero section. Do not generate a replacement avatar. The user will provide the model asset.

## 4. Visual design system

### Color palette

| Token | Value | Usage |
|---|---|---|
| Background | `#0A0A0A` | Main page background |
| Surface | `#171717` | Cards and panels |
| Primary accent | `#C6FF00` | CTAs, active states, highlights |
| Primary text | `#F5F5F5` | Headings and important copy |
| Secondary text | `#A3A3A3` | Body text and descriptions |
| Borders | `#303030` | Subtle dividers |
| Secondary accent | `#A3E635` | Limited gradient and hover effects |

Use neon lime sparingly. It should guide attention rather than cover every surface. Most of the website should remain dark and neutral.

Keep the accent color consistent across buttons, icons, selected navigation states, cursor effects, and 3D lighting.

### Typography

Use a strong display font paired with a highly readable body font.

Preferred combination:
- **Space Grotesk:** headings, hero text, project titles.
- **Inter:** body text, navigation, forms, descriptions.
- **JetBrains Mono:** small labels, technical metadata, code-inspired details.

Load fonts through a reliable font provider or local font files. Use responsive typography with `clamp()` so headings scale smoothly across screen sizes.

Headings should be large, tightly spaced, and editorial. Body copy should remain comfortable to read. Avoid using more than three font families.

### Art direction

- Black canvas with a subtle grain texture.
- Lime-green glow used behind the avatar and selected elements.
- Thin borders and restrained glass effects.
- Custom cursor on desktop, with a normal accessible cursor on mobile.
- Abstract geometric elements inspired by nodes, code, and 3D wireframes.
- Large typography and generous spacing.
- Asymmetrical compositions balanced by a clear grid.
- Small technical labels that add personality without clutter.

Avoid excessive neon, constant spinning objects, generic AI-generated backgrounds, and unnecessary gradients.

## 16. Animation and interaction specification

The site should feel fluid, but animation must support the content rather than distract from it.

### Page entrance
- Fade and slide the hero content into view.
- Reveal the heading in short word or line groups.
- Bring the avatar into view with a subtle scale and opacity transition.
- Stagger small labels and CTAs.

### Scroll interactions
- Reveal section headings as they enter the viewport.
- Animate skill cards with a slight stagger.
- Use restrained image transitions in the project gallery.
- Animate the current-focus connector.
- Avoid pinning every section or forcing users through long scroll animations.

### Hover and pointer
- Custom cursor follower on desktop only, if it remains responsive.
- Subtle cursor response on project cards.
- Animated buttons with a small arrow or background transition.
- Interactive icon movement on focused controls.
- Optional magnetic CTA effect with minimal displacement.

### Loading and transitions
- Use a lightweight loading state for the 3D model.
- Avoid an unnecessary full-screen loading animation.
- Ensure the hero content appears even if the model takes longer to load.
- Prevent layout shifts by reserving space for media and the 3D canvas.

### Technical constraints
- Use Framer Motion for DOM animations.
- Use React Three Fiber and Drei for the 3D scene.
- Use CSS transitions for simple hover states.
- Do not introduce multiple animation libraries that duplicate functionality.
- Prefer transform and opacity animations.
- Dynamically import or defer the 3D scene if this improves initial loading.
- Respect `prefers-reduced-motion`.

## 20. Accessibility and performance

Accessibility:
- Semantic HTML.
- Keyboard-accessible navigation and controls.
- Visible focus states.
- Adequate text contrast.
- Alternative text for informative images.
- Labels and validation messages for form fields.
- Reduced-motion support.
- No information conveyed by color alone.

Performance:
- Compress project screenshots.
- Use modern image formats such as WebP or AVIF where suitable.
- Lazy-load below-the-fold imagery.
- Optimize the GLB model and its textures.
- Limit unnecessary WebGL effects.
- Avoid loading the 3D scene before it is needed if doing so improves performance.
- Prevent layout shifts.
- Test on a mid-range mobile device and a slower connection.

Aim for strong Core Web Vitals and a Lighthouse performance score of 90 or above where practical. Treat this as a target to measure, not a guaranteed result.
